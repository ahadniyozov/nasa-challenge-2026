# CLAUDE.md — контекст проекта для Claude Code и других ИИ-ассистентов

## Что это

**GO / NO-GO: Mission Control** — игра для NASA Space Apps Challenge 2026, челлендж «Space Mission Design Game».

Игрок получает заказ (например, «найти лесные пожары»), собирает спутник из деталей, выбирает орбиту, ракету и наземные станции, запускает его и летает. В конце отчёт проверяет каждое требование заказчика (✅/❌) и объясняет, **почему** миссия провалилась и какую деталь поменять.

- **Аудитория:** от школьников 10+ до студентов. Игра должна быть понятна пятикласснику с первого экрана.
- **Команда:** 3 разработчика. Тимлид — Ахад (`ahadniyozov`), соавторы — `ulmasoy`, `xvvoidd`.
- **Текущая цель:** перевести 2D-игру в 3D, не меняя правил. План и раздел задач по людям — в `TASKS-3D.md`. Его нужно прочитать перед любой работой над 3D.

## Команды

```bash
npm install
npm run dev               # http://localhost:5173 (игра с 3D-полётом; ?2d — 2D-полёт)
npm run typecheck         # engine + web + server
npm test                  # vitest: движок + apps/web (sim.test.ts)
npm run check:missions    # баланс: у каждой миссии есть решение, стартовый спутник её не решает
npm run build
node scripts/bot-2d.mjs [http://localhost:5199/?all] [missionId]   # бот играет миссии в браузере в 3D (?all&2d — в 2D); нужны dev-сервер и playwright
```

Перед любым PR должны проходить: `typecheck`, `test`, `check:missions`, `build` (то же проверяет CI в `.github/workflows/ci.yml`).

## Главный принцип: правила из движка

Каждый параметр полёта считает `analyse(build, mission)` в `config.ts` из бюджетов движка:

- **тень:** доля тени = настоящая геометрия орбиты (≈37% на 550 км, 5% на ГСО);
- **энергия:** разряд батареи в тени и заряд на солнце — из энергобаланса;
- **передача:** скорость = скорость антенны × коэффициент расстояния ÷ размер фото прибора;
- **станции:** число станций за виток — из реальных пролётов над выбранными станциями;
- **срок:** время до конца = min(жизнь орбиты + двигатель, ресурс платформы × 1,5). Причина конца — `decay` (упал) или `wearout` (износился);
- **досягаемость:** `reachesTargets` = наклон орбиты против широты цели (только у миссии со свойством `farNorth`);
- **ночная съёмка и чёткость:** `nightVision` — из `INSTRUMENT_INFO`; `sharp` — разрешение на этой высоте ≤ `maxResolutionM` миссии;
- **манёвренность:** скорость смены полосы падает с массой.

**3D и любые другие визуальные режимы меняют только внешний вид.** Цифры и правила меняет только тимлид, и после изменения обязательно прогоняются `check:missions` и бот.

|---|---|---|---|---|

| 4 | weather | 12 снимков ураганов, непрерывно | ГСО + тяжёлая ракета + прочный корпус | выбор орбиты под задачу |
| 5 | spaceweather | 14 измерений, 3 солнечные бури | защищённый компьютер (или безопасный режим ПРОБЕЛ / 🛡️) | радиация |
| 6 | mapping | 12 фото ≤ 5 м, 5 лет, $42M | телескоп, X-band, прочный корпус, большие крылья, батарея L, память 12 | всё сразу, бюджет впритык |

**Звёзды:**
- ★ — выполнены все требования, кроме одного, и доставлено ≥ половины цели;
- ★★ — выполнены все требования;
- ★★★ — все требования и доставлено ≥ 1,5 × цель.

Следующая миссия открывается после ≥ 1 ★; `?all` открывает все миссии.

**Инварианты баланса** (проверяются `check:missions` и ботом):
- решение-образец каждой миссии выполняет все требования;
- стартовый или тестовый спутник их не выполняет (на миссиях с бурями обычный компьютер проходит только с безопасным режимом).

## Соглашения

- TypeScript strict, без `any`. Стек: React 19, @react-three/fiber 9, drei 10, three 0.187, zustand 5, Vite 8. Новые зависимости — только по согласованию.
- Тексты интерфейса — только `t('English text')`; русский перевод в `src/i18n/ru-2d.ts` / `ru-missions.ts`. Шаблоны: `t('Year {n} of {m}', { n, m })`.
- На canvas не рисовать эмодзи: в части браузеров их нет, поэтому цели и станции рисуются фигурами (`drawTarget` в `Flight2D.tsx`).
- `localStorage` — только в try/catch (в приватном режиме бросает исключение).
- Хуки для бота: `window.__g2d` / `window.__g3d` (SimState), `__g3dMove`, `__g3dSafe`, `window.__simBot(state, useSafe)` (тот же бот, что в тестах), `window.__g2dMove(±1)`, `window.__g2dSafe(on)`, `window.__g2dPlay(missionId, buildPatch, isTest)`. Для 3D добавить такие же `__g3d*`.
- Ассеты: свои модели из примитивов или CC0 с указанием источника. Без логотипов NASA и фото людей. Текстуры Земли — NASA Blue/Black Marble в `public/textures/`.
- Телефон обязателен: портрет, касания, без горизонтальной прокрутки, ≥ 30 fps.

## Дизайн (инженерный центр NASA)

- Экраны проектирования — светлые «документы миссии», полёт и запуск — тёмный космос. Токены цветов в `apps/web/src/game2d/theme.css`: `--paper`, `--ink`, `--steel`, `--rule`, `--orange` (только для главной кнопки), `--kapton`, `--go`, `--nogo`, `--caution`, `--space`.
- Шрифты: Barlow (текст) и Barlow Condensed (заголовки, числа, вердикт GO / NO-GO). Кириллицы в Barlow нет, поэтому русский (временный) показывается запасным шрифтом.
- В интерфейсе нет эмодзи: иконки рисуются SVG, сообщения — обычным текстом. Требования нумеруются REQ-1…, в отчёте те же номера проверяются.
- Кнопка запуска: «GO for launch» → «Launch anyway» (энергия или батарея выше нормы) → «NO-GO» (ракета или бюджет не позволяют).
