## 0. Общий контекст (читают все)

**Что за проект.** Игра для NASA Space Apps Challenge 2026, челлендж «Space Mission Design Game». Игрок получает заказ (например, «найти лесные пожары»), собирает спутник из деталей, выбирает орбиту, ракету и наземные станции, запускает его и летает. В конце отчёт проверяет каждое требование заказчика (✅/❌) и объясняет, **почему** миссия провалилась и какую деталь поменять.

**Репозиторий:** `github.com/ahadniyozov/nasa-challenge-2026`, монорепо на npm workspaces.

```
packages/engine/           чистый TypeScript: физика орбит, бюджеты (масса, энергия, данные, деньги, срок), каталог деталей, тесты (vitest)
apps/web/                  Vite + React 19 + @react-three/fiber 9 + drei 10 + three 0.187 + zustand 5
  src/game2d/              ТЕКУЩАЯ ИГРА (2D), её и переводим в 3D
    missions.ts            6 миссий: заказчик, требования, приборы, какие детали можно менять, стартовый спутник
    config.ts              SLOTS (детали), analyse(build, mission) → бюджеты и FlightParams для полёта
    Game2D.tsx             экраны: карьера → бриф → (запуск) → полёт → отчёт → сборка
    Flight2D.tsx           полёт: вертикальный скроллер, 3 полосы, цели, мусор, станции, тень, бури
    Launch2D.tsx           анимация запуска (canvas)
    SatelliteArt.tsx       SVG-картинка спутника в сборке
    missions.check.ts      проверка баланса: npm run check:missions
  src/scenes/              старые 3D-сцены (Hangar, Launch, Orbit, Spacecraft): брать как основу, переписывать можно
  src/i18n/                перевод: useT() → t('English key'); русский временный, по умолчанию будет английский
  public/textures/         earth-day.webp, earth-night.webp (NASA Blue Marble / Black Marble)
scripts/bot-2d.mjs         бот проходит все миссии в браузере (playwright)
apps/server/               socket.io: комнаты и лидерборд
deploy/                    Docker + Caddy
```

**Запуск:** `npm install`, `npm run dev` (http://localhost:5173). Проверки: `npm run typecheck`, `npm test`, `npm run check:missions`.

**Главный принцип игры.** Каждое число в полёте берётся из проекта игрока через `analyse()`: длина тени, расход батареи, скорость передачи, память, срок жизни, разрешение камеры, досягаемость широт. **3D только меняет то, как это выглядит. Правила и цифры не меняются.**

**6 миссий (от лёгкой к сложной):**

| # | Миссия | Цели в полёте | Чему учит |
|---|---|---|---|
| 1 | Первое фото из космоса | ✦ звёздочки | фото считается только после станции; рация слишком медленная |
| 2 | Лесные пожары | 🔥 огонь | тень Земли, память, падение низкой орбиты |
| 3 | Полярные льды | 🧊 айсберги | наклон орбиты: низкая орбита не долетает до 75° с.ш.; срок 5 лет |
| 4 | Ураганы | 🌀 вихри | геостационар видит одно место без перерыва, нужна тяжёлая ракета |
| 5 | Космическая погода | облака частиц | солнечные бури: безопасный режим или защищённый компьютер |
| 6 | Подробная карта | 🏙️ города | всё сразу: телескоп, большие файлы, тесный бюджет |

**Цель перехода в 3D.** Те же экраны и та же логика, но:
- полёт выглядит как полёт над настоящим 3D-глобусом;
- сборка показывает 3D-модель спутника, которая меняется от каждой детали;
- запуск — 3D-ракета, размер которой зависит от выбранной;
- карьера — глобус с точками миссий.

2D-версия остаётся как запасной режим (`?2d`) для слабых телефонов.

### Общие контракты (не менять без согласования в чате команды)

```ts
// apps/web/src/game2d/config.ts (уже есть)
type SlotId = 'camera' | 'body' | 'panels' | 'battery' | 'antenna' | 'memory' | 'orbit' | 'rocket' | 'stations' | 'shield' | 'thruster' | 'computer';
type Build = Record<SlotId, string>;          // например { camera: 'cam-thermal', orbit: 'sso-550', rocket: 'heavy', ... }
function analyse(build: Build, m: Mission): Analysis;   // Analysis.flight: FlightParams

// apps/web/src/game2d/missions.ts (уже есть)
interface Mission { id; num; title; targets: { kind: 'star'|'fire'|'ice'|'storm'|'particle'|'city'; band: [north, south] }; goal; years; storms; ... }

// apps/web/src/game2d/Flight2D.tsx (уже есть)
interface FlightStats { delivered; captured; lostInMemory; survived; decayed; wornOut; hits; batteryOuts; memoryFull; nightMissed; blurry; outOfReach; stormHits; stormsSafe; stormsSurvived }

// НОВОЕ — делает Разработчик 1 (Ахад), используют 2D и 3D полёт
// apps/web/src/game2d/sim.ts
interface SimInput { lane: 0 | 1 | 2; safe: boolean }
interface SimObject { id: number; kind: 'target' | 'debris' | 'station'; lane: -1 | 0 | 1 | 2; ahead: number; done: boolean }
  // ahead — расстояние до спутника в секундах полёта (>0 впереди, <0 позади). lane -1 = цель вне досягаемости орбиты
interface SimState {
  t: number; laneY: number; battery: number; memory: number; delivered: number; hearts: number;
  shadow: boolean; contact: boolean; asleep: boolean; storm: 0 | 1 | 2; ended: boolean;
  objects: SimObject[]; stats: FlightStats;
  events: SimEvent[];   // события этого кадра: 'photo' | 'hit' | 'memoryFull' | 'dark' | 'blurry' | 'outOfReach' | 'stormHit' | 'stormSafe' | 'batteryOut' | 'decay' | 'wornOut' | 'end'
}
function createSim(p: FlightParams, m: Mission, seed?: number): SimState;
function stepSim(s: SimState, dt: number, input: SimInput): void;   // мутирует s, без DOM и рендера
```

### Часть Б. 3D-полёт (дни 2–4)

#### Как должно выглядеть
- **Глобус:** настоящий 3D-глобус Земли (`public/textures/earth-day.webp` + `earth-night.webp`), шейдер день/ночь с плавным терминатором и лёгкая атмосфера (свечение по краю).
- **Полёт и камера:** спутник летит над поверхностью по своей трассе, камера сзади-сверху (третье лицо). Земля «едет» под спутником, движение идёт вперёд от камеры.
- **3 полосы:** три параллельные дорожки вдоль трассы (полупрозрачные линии на высоте полёта). ← → или A/D меняют полосу, на телефоне — касание левой или правой половины экрана. Спутник плавно смещается и наклоняется; скорость смены полосы = `FlightParams.laneSpeed` (тяжёлый спутник поворачивает медленнее).
- **Объекты из `SimState.objects`:** позиция вдоль трассы = `ahead × скорость`, поперёк = полоса.
  - **Цели** — свой вид для каждого `Mission.targets.kind`: огонь (частицы), айсберг, вихрь урагана (вращающийся диск), облако частиц, город (кубики-дома), звезда. Простые меши, без тяжёлых моделей.
  - **Мусор** — вращающиеся угловатые обломки.
  - **Станции** — антенна на поверхности и зелёный конус связи до спутника, пока есть `contact`.
  - **Цели вне досягаемости** (`lane -1`) видны полупрозрачными за красной линией «граница орбиты» со стороны севера.
- **Тень Земли:** когда `shadow = true`, спутник входит на ночную сторону глобуса: темно, видны огни городов. Это должно совпадать с полосой тени на HUD.
- **Особые орбиты:**
  - **Геостационар (`alwaysInContact`):** камера дальше, Земля почти неподвижна, видно полдиска.
  - **Солнечная буря (`storm 1/2`):** оранжевый свет со стороны Солнца, вспышки частиц. Безопасный режим — жёлтое кольцо вокруг спутника, кнопка 🛡️ / ПРОБЕЛ.
- **События (`SimState.events`):** вспышка камеры при фото, тряска камеры при ударе, «зелёные пакеты данных», летящие к станции при передаче.
- **HUD:** взять из `Flight2D.tsx` (HTML поверх canvas: счёт, память, жизни, батарея, год/виток, подсказки) и не переделывать. Спутник в полёте взять из `game3d/SatelliteModel.tsx` разработчика 2 (до готовности — простой куб с панелями).

#### Технически
- `@react-three/fiber` + `drei`. Цикл: в `useFrame` вызывать `stepSim(state, dt, input)` и обновлять меши через ref, **без setState каждый кадр**. HUD обновлять ~10 раз в секунду.
- Объекты хранить в пулах (`InstancedMesh` для мусора и частиц), не создавать меши каждый кадр.
- Производительность: ≥ 60 fps на ноутбуке, ≥ 30 fps на среднем Android. Ограничить `dpr` до 1.5 на телефонах, без тяжёлого постпроцессинга.
- Отдать наружу `window.__g3d = state` и `window.__g3dMove(d)`, `window.__g3dSafe(on)` для бота, как в 2D.

#### Критерии готовности 3D-полёта
- Все 6 миссий проходятся в 3D, и итоговые `FlightStats` такие же, как в 2D при том же сиде и вводе.
- Видно: тень, станции, цели всех 6 типов, бури, линию досягаемости (миссия 3 на низкой орбите), «висящий» геостационар (миссия 4).
- Работает на телефоне в портретной ориентации.

### Часть В. Склейка

1. **Режимы:** `?2d` — 2D-версия; по умолчанию 3D; автопереход на 2D, если WebGL недоступен.
2. **Склейка:** принимать PR разработчиков 2 и 3, следить, чтобы `typecheck`, `test`, `check:missions` и бот проходили.
- Финальный прогон бота по всем 6 миссиям в 2D и 3D, проверка на 2–3 телефонах.

## Разработчик 2 — 3D-спутник, сборка, запуск, карьера

**Ты отвечаешь за:** всё 3D вне полёта. Твои файлы: `apps/web/src/game3d/SatelliteModel.tsx`, `Hangar3D.tsx`, `Launch3D.tsx`, `Career3D.tsx` (новые). Можно брать куски из `src/scenes/*` (старые HangarScene, LaunchScene, Spacecraft).

**Начни с `SatelliteModel.tsx`** — она нужна разработчику 1 для полёта, отдай первую версию в конце дня 1.

### Задачи

1. **`SatelliteModel.tsx` — 3D-модель спутника из `Build`** (`<SatelliteModel build={build} mission={m} />`). Каждая деталь видна:
   - **корпус:** размер по `analyse(build, m).design.busId`: 3U (вытянутый), 12U, 150 кг, 800 кг;
   - **панели:** на корпусе, малые крылья или большие крылья;
   - **антенна:** штырь-рация, патч, тарелка;
   - **батарея и память:** индикаторы на корпусе;
   - **прибор:** 7 видов (камера, тепловая, телескоп-труба, гиперспектр, радиометр-тарелка, магнитометр на штанге, счётчик радиации);
   - **щит:** полупрозрачная сфера; **двигатель:** сопло; **защищённый компьютер:** метка «RAD».

   Модель одна для сборки и для полёта, поэтому лёгкая: простые примитивы, ≤ 3000 треугольников.
2. **`Hangar3D.tsx` — экран сборки.** Слева 3D-модель (вращение мышью или пальцем, авто-вращение), справа те же слоты и шкалы, что сейчас в `BuildScreen` из `Game2D.tsx` (логику не трогать, только заменить `SatelliteArt` на 3D-сцену). При выборе детали камера коротко подлетает к ней, а деталь подсвечивается.
3. **`Launch3D.tsx` — запуск** (замена `Launch2D.tsx`, тот же интерфейс `{ build, onDone }`):
   - **сценарий:** отсчёт 3-2-1, старт с дымом, набор высоты, небо темнеет, отделение ступени, раскрытие обтекателя, выход спутника (той же `SatelliteModel`) с раскрытием панелей;
   - **ракета зависит от `build.rocket`:** попутный запуск (маленькая), средняя, тяжёлая (с боковыми ускорителями);
   - **в подписи** — высота орбиты из `build.orbit`;
   - **пропуск:** клик или клавиша; длительность ≤ 9 с.
4. **`Career3D.tsx` — карьера.** Глобус, на нём 6 точек миссий в своих местах (пожары — Сибирь/Канада, льды — Гренландия, ураганы — Атлантика, город — любой мегаполис и т.д.). У точки звёзды и замок, наведение показывает карточку миссии, клик ведёт в бриф. Данные — из `MISSIONS` и прогресса (`localStorage` ключ `g2d-progress-v1`, логика уже в `Game2D.tsx`).
5. **Единый стиль интерфейса:** тёмный «пульт управления», бирюзовые акценты, крупные кнопки. Переменные цветов уже есть в `runner.css` (`--r-*`).


### Критерии готовности
- Любая комбинация деталей во всех 6 миссиях даёт корректную модель без пересечений и висящих в воздухе частей (проверить скриптом: перебор вариантов + скриншоты).
- Запуск выглядит по-разному для трёх ракет.
- Карьера на глобусе работает мышью и пальцем; на телефоне ≥ 30 fps.

## Разработчик 3 — контент NASA, звук, язык, деплой, тестирование

**Ты отвечаешь за:** то, что делает проект убедительным для жюри и работающим у всех. Твои файлы: `apps/web/src/game3d/audio.ts`, `apps/web/src/content/*` (карточки миссий NASA, ресурсы), `apps/web/src/i18n/`, `deploy/`, `scripts/`.

### Задачи

1. **Экран «В реальности» в отчёте.** После победы показывать карточку настоящей миссии NASA, которая решает ту же задачу:
   - Первое фото → CubeSat-программа NASA CSLI;
   - Пожары → MODIS/VIIRS (FIRMS);
   - Льды → ICESat-2;
   - Ураганы → GOES;
   - Космическая погода → миссия по космической погоде (подобрать и проверить);
   - Карта → Landsat.

   В карточке: 2–3 факта, картинка-схема без фото людей и ссылка на страницу nasa.gov / science.nasa.gov. Каждый факт сверить с источником.
2. **Экран «NASA Resources»** (из меню): какие ресурсы челленджа и данные NASA использованы и где именно в игре, со ссылками.
3. **Английский по умолчанию.** Русский оставить переключателем до финала, потом удалить файлы `ru*.ts` (они помечены TEMPORARY).
4. **`audio.ts` — звук** без файлов, через WebAudio (синтез):
   - звуки: щелчок интерфейса, фото, писк станции, сигнал бури, удар, отсчёт, рёв двигателя на старте, победа и поражение;
   - кнопка выключения звука, громкость в `localStorage` (в try/catch).
   - Экспорт `sfx.photo()`, `sfx.hit()` и т.д. Разработчик 1 вызывает их по `SimState.events` в полёте, разработчик 2 — в запуске и сборке.
5. **Деплой** на свой домен (`deploy/`, Docker + Caddy), проверить HTTPS и сжатие текстур.

- **Тестирование:** после каждой склейки пройти все 6 миссий на ноутбуке и телефоне, записать баги в issues на GitHub с шагами и скриншотом.
- **Материалы для заявки:** сценарий видео на 30–60 с, текст описания проекта, список использованных ресурсов NASA.

### Критерии готовности
- В отчёте каждой миссии есть карточка «В реальности» с проверенными фактами и рабочей ссылкой.
- Экран «NASA Resources» открывается из меню, все ссылки рабочие.
- Звук есть во всех ключевых моментах и выключается одной кнопкой.
- Игра открывается по HTTPS на нашем домене, по умолчанию на английском.

## Правила для всех (вставь в свою нейросеть вместе со своим разделом)

1. **Не меняй правила и цифры баланса** (`packages/engine`, `config.ts`, `missions.ts`, `sim.ts`) — это зона разработчика 1 (Ахад). Нужно другое число — напиши в чат команды.
2. **Работай только в своих файлах.** Общие файлы (`Game2D.tsx`, `main.tsx`, `i18n`) меняет разработчик 1 по твоей просьбе или в твоём PR с пометкой.
3. **Git:** своя ветка (`dev1/flight3d`, `dev2/hangar3d`, `dev3/content` и т.п.), маленькие коммиты, PR в `main`. Перед PR: `npm run typecheck && npm test && npm run check:missions`.
4. **TypeScript strict**, без `any`. React 19 + r3f 9 + drei 10 + three 0.187: не ставить другие версии и новые тяжёлые библиотеки без согласования.
5. **Тексты интерфейса** — только через `t('English text')` из `useT()`; русский перевод добавлять в `src/i18n/ru-*.ts`.
6. **Ассеты:** только свои модели из примитивов или ассеты с открытой лицензией (CC0) и указанием источника в `README`. Никаких логотипов NASA и фото людей. Текстуры Земли — уже лежащие NASA Blue/Black Marble.
7. **Производительность:** бандл 3D-части ≤ 1,5 МБ gzip, текстуры ≤ 2 МБ каждая, на телефоне ≥ 30 fps.
8. **Проверка на телефоне** обязательна: портретная ориентация, касания, без горизонтальной прокрутки.
9. **Перед тем как сказать «готово»** — скриншот или короткое видео экрана в чат команды.
